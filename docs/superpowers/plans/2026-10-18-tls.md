# TLS 接入实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 客户端通过 TLS 连接公网入口，服务端保持在 nginx stream 后面只监听回环地址；随后补 PROXY protocol 获取真实客户端 IP。

**Architecture:** nginx stream 终结 TLS，转发到 `127.0.0.1:9100`；客户端使用 OpenSSL 原生 socket TLS，验证自建 CA 和证书 SAN。服务端增加 PROXY v1/v2 解析，登录限流使用真实 IP。

**Tech Stack:** OpenSSL 4.0.3（Windows 客户端）、nginx stream（Linux）、现有原生 socket 网络线程。

**Status:** 已实施并验证（2026-10-18）。

## Global Constraints

- 客户端继续使用原生 Winsock + 独立线程，TLS 用 OpenSSL 包装同一个 socket。
- 服务端只监听 `127.0.0.1`，公网只开放 nginx 9443。
- 客户端必须校验证书链和主机/IP，不能关闭验证。
- 私钥权限 600；CA 私钥不进入客户端。
- PROXY protocol 只信任本机 nginx。

## 实施验证结果（2026-10-18）

| 验证项 | 结果 |
|---|---|
| Windows 客户端 OpenSSL | OpenSSL 4.0.3，MinGW 直接链接成功 |
| TLS 握手 | TLS 1.3，客户端校验证书链 + IP SAN |
| 证书拒绝 | 使用系统默认 CA 连接失败（`SSLCertVerificationError`） |
| nginx | 9443 TLS 终结，转发 127.0.0.1:9100 |
| PROXY protocol | nginx v1 头解析成功，真实 IP 为 192.168.2.117 |
| 服务端监听 | `127.0.0.1:9100`，外部 9100 不可直连 |
| 客户端登录 | Qt 通过 9443 TLS 登录成功，房间/历史正常 |
| 日志 | 记录 `login ok user=demo ip=192.168.2.117` |
| `ctest` | 3/3 通过 |

实现要点：
- 客户端 TLS 握手后把 socket 切为非阻塞，避免 `SSL_read` 在 TLS 控制记录上阻塞导致登录帧发不出去。
- 服务端新增 PROXY v1/v2 解析，登录限流使用真实 IP。
- 证书：`/etc/chatroom/certs/ca.crt`、`chat.crt`；客户端 CA 在 `client/certs/ca.crt`。
- nginx 配置：`deploy/nginx-chat-stream.conf`，开启 `proxy_protocol on`。
