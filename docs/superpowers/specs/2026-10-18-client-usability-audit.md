# Qt 客户端 MVP 差距审计与可用版路线

**日期：** 2026-10-18

**范围：** `chatroom/client` 当前 Qt 5.15 Widgets 客户端；服务端现有协议作为约束。

## 1. 结论

当前客户端是“核心链路 MVP”，不是“日常可用聊天客户端”。

已验证可用的主链路：

- 登录、注册、Token 自动恢复、退出登录
- 房间列表、加入房间、在线成员
- 群聊/私聊纯文本发送与接收
- 房间/私聊历史分页
- 私聊未读数、任务栏闪烁、托盘气泡
- TLS、断线指数退避重连
- 自己的推送按 `sender_id` 忽略，避免重复

但聊天最基础的三件事还不完整：

1. **消息是否发出去**：没有发送中/已发送/失败状态，网络断开发送会静默丢失。
2. **聊天界面是否像聊天**：纯文本日志式渲染，没有气泡、日期分组、失败重发。
3. **断线/错误是否可见**：只有底部状态栏，输入框在离线时仍可操作。

## 3. 差距矩阵

### P0：聊天基础可用性（客户端即可完成）

| 缺口 | 影响 | 改哪里 | 工作量 |
|---|---|---|---|
| 消息状态：发送中/已发送/失败 | 用户不知道消息是否送达 | `MainWindow` + 新消息状态模型 | 中 |
| 失败消息保留 + 重发 | 断网时消息直接丢 | 新 Outbox + 发送管线 | 中 |
| 发送失败不清空/不假装成功 | 当前本地回显会误导 | `onSendClicked` + `sendFrame` | 小 |
| 聊天视图：气泡、时间、日期分隔 | 现在像日志，不像聊天 | `MessageRenderer` + `MainWindow` | 中 |
| UTC 转本地时间 | 历史消息时间显示错误 | `MessageTime` + 渲染 | 小 |
| 连接横幅 + 离线禁用发送 | 断线时仍可输入，体验混乱 | `MainWindow` | 小 |
| 登录失败显示在登录页 | 错误藏在底部状态栏 | `handleError` + `LoginPage` | 小 |
| 发送响应/错误关联到消息 | 无法标记具体消息失败 | seq → client_msg_id 映射 | 中 |
| 客户端单元测试 | 改发送/渲染没有回归保护 | 新增 `client/tests` | 中 |

### P1：找人 + 客户端产品化

| 缺口 | 影响 | 改哪里 | 工作量 |
|---|---|---|---|
| 用户搜索、发起私聊 | 只能从房间成员里找 | 新协议 `USER_SEARCH` + 服务端 DAO + 客户端搜索框 | 中 |
| 联系人列表 | 最近私聊之外没有联系人 | 服务端关系表或本地收藏 | 大 |
| 设置页 | 服务器/TLS/通知不可配置 | 客户端 Settings 对话框 | 中 |
| 客户端日志/崩溃日志 | 出问题无法排查 | Qt message handler + 日志文件 | 中 |
| 托盘菜单/最小化到托盘 | 关闭窗口就退出 | `QSystemTrayIcon` + `QMenu` | 小 |
| 自动登录可取消 | 服务器不可达时卡在恢复页 | 登录页取消按钮 + 网络停止 | 小 |
| 安装包/图标/版本信息 | 还不能正式分发 | `.rc` + Inno Setup/zip + 图标 | 中 |
| 心跳超时/PONG 校验 | 半开连接不会重连 | `NetworkThread` | 中 |
| Token 加密存储 | 明文 Token 有风险 | DPAPI/凭据管理器 | 中 |

### P3：群组、多端、运营

| 缺口 | 说明 |
|---|---|
| 自建群/邀请/踢人/管理员 | 当前只有固定房间 |
| 群公告/群昵称/群头像 | 群资料体系 |

## 4. 第一阶段范围

**只做 P0，且不改协议、不改服务端。**

目标：让客户端从“能跑”变成“消息不丢、状态可见、界面像聊天”。

包含：

1. 客户端测试工程与核心消息类型
2. 进程内 Outbox：发送中/失败/重发/超时
3. 聊天 HTML 渲染：气泡、时间、日期分隔、失败重发链接
4. 发送响应/错误按 seq 关联消息
5. 历史与实时消息统一进入消息模型
6. UTC → 本地时间
7. 连接横幅、离线禁用发送、登录页错误
8. 构建脚本、README、手工验收

不包含：

- 图片/文件
- 用户搜索/联系人
- 群管理
- 多端
- 离线推送
- 跨进程持久化 Outbox
- 协议变更

### 关键设计决定

- **保留 `QTextBrowser` + HTML**，不引入 `QListView`/自定义 delegate。第一阶段先降低风险，消息量按每页 50 条控制。
- **Outbox 只在进程内保留**。应用退出后未发送消息丢失，这是第一阶段已知限制；持久化放 P1。
- **服务端时间按 UTC 解释**，只在显示层转本地时区。
- **重发使用原 `client_msg_id`**，服务端已有幂等去重。
- **失败消息不自动重发**，由用户点“重发”；避免在房间未重新加入时自动发送失败。
- **不修改协议**：现有 `CHAT_SEND_RESP` / `PRIVATE_SEND_RESP` 已返回 `message_id + created_at`，错误帧也带请求 seq。

## 5. 验收标准

- 断网后发送：消息显示“发送失败”，不会显示成已发送；输入内容不丢。
- 恢复连接后点击“重发”：同一条消息只出现一次，状态变为“已发送”。
- 10 秒未收到发送响应：自动标记失败，可重发。
- 历史消息时间显示为本地时间，跨天有日期分隔。
- 当前聊天中失败消息切换上下文再回来仍可看到并重发（进程内）。
- 登录失败时错误显示在登录页，按钮恢复可用。
- 断线时显示红色连接横幅，发送按钮禁用；恢复后横幅消失、发送恢复。
- 消息内容含 `<script>` 等字符只作为文本显示。
- 客户端测试全部通过，应用构建通过。
